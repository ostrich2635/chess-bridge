# Project Overview
Build a static, client-side web application (HTML, CSS, Vanilla JavaScript) to be hosted on GitHub Pages. 

The app acts as a bridge between Chess.com and Lichess. It monitors a player's Chess.com account, detects when they finish a game, and dynamically generates a button to instantly import that game into Lichess for analysis.

## Tech Stack
* **Frontend:** HTML5, CSS3, Vanilla JavaScript (no build tools or frontend frameworks required).
* **Backend:** None. All API calls must be made directly from the client's browser.
* **Hosting:** GitHub Pages.

## UI Requirements
Create a clean, modern, and responsive user interface with the following elements:
1. **Inputs:**
   * A text input for the `Chess.com Username`.
   * A password-type input for the `Lichess Personal Access Token` (with a link to `https://lichess.org/account/oauth/token` for users to get one).
2. **Controls:**
   * A "Start Monitoring" button to begin checking for completed games.
   * A status indicator (e.g., "Waiting for game to finish...", "Game found!").
3. **Dynamic Output Area:**
   * An empty container area where the "Analyze on Lichess" button will be injected after a game completes.

## Core Logic & API Workflow

### 1. Polling for a Completed Game
When the user clicks "Start Monitoring", the app should begin polling the Chess.com PubAPI every 15-20 seconds to find the latest game.
* **Endpoint 1:** `GET https://api.chess.com/pub/player/{username}/games/archives`
  * Get the last URL in the `"archives"` array (the current month).
* **Endpoint 2:** `GET {latest_month_url}`
  * Look at the last game in the `"games"` array.
  * Compare the URL or ID of this game to the last known game. 
  * If a *new* game appears, stop polling, extract the `"pgn"` data, and move to Step 2.

### 2. Injecting the Button
Once a new game is detected:
* Update the UI status to indicate a game just finished.
* Dynamically generate a button in the UI that says "Analyze Latest Game on Lichess".
* Store the PGN data of that specific game in memory, attached to the button's event listener.

### 3. Pushing to Lichess
When the user clicks the dynamically generated "Analyze" button:
* Make a request to the Lichess Import API.
* **Endpoint:** `POST https://lichess.org/api/import`
* **Headers:** 
  * `Authorization: Bearer {lichess_token}`
  * `Content-Type: application/x-www-form-urlencoded`
* **Body:** `pgn={pgn_data}`
* **Action:** The API will return a JSON response with a `"url"` field. Open that URL in a new browser tab.

## Important Constraints
* **CORS Handling:** Both the Chess.com PubAPI and the Lichess Import API support CORS for client-side requests, so standard `fetch()` calls will work.
* **Error Handling:** Add basic `try/catch` blocks for network errors, invalid usernames, or unauthorized Lichess tokens, and display these errors to the user in the UI.
* **No Server-side Code:** Ensure everything works in a standard `index.html` and `script.js` file so it can be deployed directly via GitHub Pages.
